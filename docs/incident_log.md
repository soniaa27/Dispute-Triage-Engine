# Incident log

Real failures met during development and operation. One row per incident; newest last.

| Date | Symptom | Root cause | Fix | Prevention |
|------|---------|------------|-----|------------|
| 2026-10-24 | Development halted: shell commands and Docker builds failed with `ENOSPC`. | Host disk full (Docker Desktop image/cache plus local files). | Freed ~25 GB on the host; resumed. | Check `docker system df` before builds; prune unused images/build cache regularly. |
| 2026-10-24 | Worker JSON logs had `run_id: null` on RQ's "Successfully completed" / "Job OK" lines. | `process_run` called `unbind_contextvars` in `finally`, removing the IDs the worker had bound around the job. | Use `structlog.contextvars.bound_contextvars` (restores the previous values) and bind IDs in a `Worker.execute_job` override. | Smoke check: `docker compose logs worker \| grep <run_id>` shows every job line. |
| 2026-10-28 | `make ingest` hung for over 15 minutes on an 8 GB Mac (process idle at ~3% CPU, swapped out); the worker image build was killed in the ingest step with `cannot allocate memory` (3.8 GB Docker VM). | `FastEmbedder.embed_passages` called fastembed's `passage_embed` without a batch size, so it used the default of 256: the corpus went through in batches padded to the longest chunk (up to 512 tokens), and attention for such a batch needs several GB. Time grew steeply with batch size (8 chunks 0.19 s, 16 chunks 1.9 s, 32 chunks 4.1 s). The model tests embedded only 6 short texts, so they never hit it. | Explicit batch size, default 8, configurable with `EMBED_BATCH_SIZE` (`ingest/embed.py`, `.env.example`). The full index now builds in about 10 s locally and the worker image builds. | `model` test `test_real_model_embeds_the_full_corpus_in_bounded_time` embeds every chunk of the real PDFs and must finish in under 120 s (a watchdog aborts it if it hangs). Run `pytest -m model` after any change to embedding or chunking. |
